# OpenSpec — структурированная документация Zeip

## Зачем

Проект Zeip — монорепозиторий Nx с приложением Next.js (`my-app`), 10 библиотеками (`libs/`), самодельным Supabase на VPS и десятками `ai_docs`-файлов. ИИ-ассистент (Cline) каждый раз «знакомится» с кодом заново и не имеет единого источника правды по архитектуре, бизнес-логике и принятым решениям.

OpenSpec — система структурированных документов, которые ИИ-ассистент читает перед началом работы. Это даёт:
- **единый источник истины** по архитектуре и бизнес-логике;
- **журнал принятых решений** (почему сделано так, а не иначе);
- **лог изменений**, который можно «скормить» ИИ перед новой задачей;
- **понимание границ модулей** и связей между ними.

## Как ИИ использует эти файлы

Перед началом любой задачи ИИ-ассистент ДОЛЖЕН прочитать в указанном порядке:

1. **`README.md`** — этот файл (правила работы)
2. **`architecture.md`** — архитектура, стек, связи между модулями
3. **`data-model.md`** — описание таблиц БД, связей, бизнес-правил
4. **`business-logic.md`** — ключевые механики
5. **`frontend.md`** — структура страниц, компоненты, контексты, роутинг
6. **`deployment.md`** — инфраструктура, деплой, скрипты
7. **`decision-log.md`** — хронология архитектурных решений

Файлы `changelog/` содержат записи о конкретных изменениях — их ИИ читает при необходимости (например, перед работой над задачей).

## Как человеку обновлять

- **Архитектурное решение** → сразу запиши в `decision-log.md` (дата, контекст, что сделано, почему, альтернативы, эффекты).
- **Изменение кода** → после завершения задачи допиши запись в `changelog/` по шаблону `template.md`.
- **Остальные файлы** обновляй по необходимости, когда архитектура, модель данных или логика существенно меняются. Избегай дублирования — если детали уже есть в `ai_docs/devel/*`, ставь перекрёстные ссылки.

## Структура

```
ai_docs/
  specs/
    README.md              ← этот файл
    architecture.md        ← архитектура и стек
    data-model.md          ← модель данных Supabase
    business-logic.md      ← бизнес-логика (карта, чаты, профили, подписки)
    frontend.md            ← структура фронтенда
    deployment.md          ← инфраструктура и деплой
    decision-log.md        ← журнал архитектурных решений
    changelog/
      template.md          ← шаблон для лога изменений
```
