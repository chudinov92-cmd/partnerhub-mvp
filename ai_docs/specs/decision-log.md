## 2026-11-12: Деплой без мутации БД — RUN_MIGRATIONS флаг

**Контекст:** `deploy-app.sh` при каждом запуске прогонял все старые SQL-миграции из репо. После ручного применения исправлений безопасности через Supabase Studio, повторный деплой откатывал эти исправления (возвращались INSERT-политики, широкие гранты, EXECUTE для anon). Деплой был заблокирован.

**Что сделано:** 
1. Миграции выключены по умолчанию — `RUN_MIGRATIONS=0`. Запуск только с `RUN_MIGRATIONS=1`.
2. Создан `security-baseline.sql` — идемпотентный файл, который приводится последним.
3. Исправлены пути в `sync-smtp-to-env-app.sh` (рабочий путь `/root/zeip/my-app/my-app/deploy/timeweb/`).
4. Расширен корневой `.gitignore` для защиты секретов.
5. Проведён аудит всех 61 SQL-миграции на конфликты с целевым состоянием безопасности.

**Почему:** Любой деплой больше не может случайно откатить безопасность. Миграции — осознанное действие с явным флагом. Security-baseline фиксирует защищённое состояние независимо от порядка миграций.

**Альтернативы:** Таблица учёта миграций (каждая выполняется один раз) — сложнее, предложено как отдельный шаг. Полный отказ от SQL-миграций в деплое — слишком жёстко, нужны для новых фич.

**Побочные эффекты:** `RUN_MIGRATIONS=1` нужно не забывать при деплое новых миграций. Security-baseline должен обновляться при изменении целевого состояния.
# Журнал архитектурных решений (Decision Log)

## 2026-09-07: Hairpin NAT для email/push dispatch

**Контекст:** pg_net из `supabase-db` не доставал `zeip.ru` через внешний DNS — контейнеры в разных Docker-сетях, hairpin NAT на VPS не настроен. Push и email не работали.

**Что сделано:** URL диспатчера изменён с `https://zeip.ru/api/push/dispatch` на `http://172.17.0.1:3001/api/push/dispatch` (внутренний bridge-адрес хоста + порт 3001 app-web). Аналогично — для email API-роутов.

**Почему:** Docker bridge гарантирует низкую latency и работает без внешнего DNS. Порт 3001 не доступен извне.

**Альтернативы:** Настройка hairpin NAT на VPS — отвергнута из-за сложности.

**Побочные эффекты:** `push_dispatch_url` в `public.app_config`. Требует синхронизации при смене IP/сетей.

## 2026-08: Вынос логики в Nx-библиотеки (рефакторинг)

**Контекст:** Весь код в `my-app/` — размытые границы модулей, медленная сборка, правки затрагивают смежное.

**Что сделано:** Поэтапный вынос в `libs/`: `auth`, `chat`, `subscription`, `notifications` (с subpath `./server`), `profile`, `map-ui`, `admin`, `analytics`, `ui`, `hooks`.

**Почему:** Изоляция ускоряет сборку (Nx кэш), предотвращает циклические зависимости, упрощает тестирование.

**Альтернативы:** Продолжать монолит — отвергнуто из-за роста codebase.

**Побочные эффекты:** Рефакторинг ~30% импортов. Часть серверных модулей (админка) пока в `my-app`.
## 2026 (historical): Self-hosted Supabase на Timeweb VPS

**Контекст:** Изначально Vercel + Supabase Cloud. Рост нагрузки и требования 152-ФЗ (ПДн) потребовали переноса на российский VPS.

**Что сделано:** Перенос Next.js → Docker на Timeweb (`app-web`); Supabase → self-hosted (Kong, PostgREST, Auth, Realtime, Studio); Postgres — полное восстановление дампа. Runbook: `timeweb-migration-runbook.md`.

**Почему:** Контроль данных, соответствие 152-ФЗ, независимость от внешних сервисов.

**Альтернативы:** Остаться на Vercel + Supabase Cloud — не соответствует ПДн.

**Побочные эффекты:** Операционный overhead (бэкапы, обновления, дисковое пространство). Настройка SMTP, SSL (Caddy), Docker networking.

## 2026 (historical): CSP nonce + `dynamic = force-dynamic`

**Контекст:** Chrome + `strict-dynamic` резал JS-бандл без nonce на странице. Next.js рендерил статический HTML без nonce.

**Что сделано:** Middleware генерирует nonce на каждый HTML-запрос. `layout.tsx`: `dynamic = force-dynamic` + `headers()`. sha256 для фиксированных inline-скриптов.

**Почему:** Без nonce Chrome блокирует все скрипты при `strict-dynamic`.

**Альтернативы:** Отказ от `strict-dynamic` — менее безопасно.

**Побочные эффекты:** Небольшое увеличение времени SSR. CSP_REPORT_ONLY=1 для отладки.

## 2026 (historical): Обфускация координат пинов

**Контекст:** Точные координаты пользователей на публичной карте — риск приватности.

**Что сделано:** Детерминированно-случайный сдвиг ~250 м (`obfuscateLatLngWithinRadius`). Seed по user_id.

**Почему:** Баланс приватности и полезности карты.

**Альтернативы:** Только город без координат — карта теряет смысл.

**Побочные эффекты:** Невозможна точная навигация (заложено). Координаты в БД — точные, обфускация на уровне UI.

## 2026-08: Hard login-wall для `/map` + paid_gate

**Контекст:** Ранее гости видели карту. После решения монетизировать продукт потребовалось ограничение доступа.

**Что сделано:** Middleware: гости с `/map` → `/`. Три тарифа Free/Pro/Pro+ с лимитами. Гостевой CJM не реализован.

**Почему:** Упрощение модели монетизации: лендинг → регистрация → вход → подписка.

**Альтернативы:** Soft paywall для гостей — отвергнут (сложность, неоднозначные метрики).

**Побочные эффекты:** Падение регистраций, рост качества конверсии. PaywallDrawer + лимиты (5 просмотров/сутки, 5 избранных).
